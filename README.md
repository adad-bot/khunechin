# خونه‌چین — نسخهٔ اجرایی (پروتوتایپ کارکردی)

اپلیکیشن طراحی و چیدمان داخلی، ساخته‌شده بر پایهٔ سند «طراحی و ساخت اپلیکیشن خونه‌چین».
این نسخه یک وب‌اپ موبایل‌محور فارسی و راست‌به‌چپ است که به‌صورت PWA روی اندروید نصب می‌شود و
بدون هیچ تغییری در منطق، با Capacitor به APK تبدیل می‌شود.

## اجرا

بدون نصب و بدون بیلد:

```powershell
# روش ۱: باز کردن مستقیم
# فایل app/index.html را در مرورگر باز کن

# روش ۲: سرور محلی (پیشنهادی برای PWA و دوربین)
node _tools/serve.js
# سپس http://127.0.0.1:7801
```

روی گوشی: صفحه را در شبکهٔ محلی باز کن، یا از منوی مرورگر «افزودن به صفحهٔ اصلی» را بزن.

## آزمون

```powershell
node _tools/test_engine.js   # ۳۶ آزمون موتور چیدمان و اندازه
node _tools/test_flow.js     # ۴۸ آزمون جریان سفارش، اصلاح، خرید، رویدادها
node _tools/drive.js         # اجرای کامل مسیر کاربر با مرورگر واقعی (CDP)
```

`drive.js` به سرور محلی روی پورت ۷۸۰۱ و Microsoft Edge نیاز دارد و خروجی تصویری
را در `_shots/` می‌نویسد.

## ساختار

```
app/
  index.html            قالب دستگاه و بارگذاری اسکریپت‌ها
  css/app.css           سیستم طراحی (پالت، تایپوگرافی، اجزا)
  js/data.js            دادهٔ اتاق نمونه، وسایل، کالاها، متن‌های محصول
  js/engine.js          موتور چیدمان، اعتبارسنجی اندازه، ساخت راهنما
  js/art.js             لوگو، صحنهٔ پذیرایی (قبل/بعد)، پلان نمای بالا — همه SVG
  js/store.js           وضعیت، ذخیره‌سازی محلی، چرخهٔ پردازش، خرید، اصلاح
  js/ui-core.js         مسیریابی، اجزای مشترک، مقایسهٔ قبل/بعد
  js/screens-a.js       آغاز، نمونه، خانه، پروژه‌ها، حساب، پشتیبانی
  js/screens-b.js       عکس، حالت طراحی، هدف، محدودیت، انتخاب وسیله، مرور
  js/screens-c.js       پلان و اندازه‌گیری، پردازش
  js/screens-d.js       نتیجه، اصلاح موضعی، راهنمای اجرا، بسته/رسید، پنل عملیات
  manifest.webmanifest  تنظیمات نصب PWA
  sw.js                 کش آفلاین
```

## آنچه واقعی است

- موتور چیدمان: ساخت دو طرح از قیدهای واقعی پروژه، رد کردن مقصد ناسازگار،
  محاسبهٔ عرض آزاد مسیر، ساخت فهرست تغییر و راهنمای اجرا با ترتیب اجرا.
- اعتبارسنجی اندازه: تبدیل «۲۱۰»، «۲٫۱۰ متر»، «210 cm» به یک مقدار؛ رد صفر/منفی/مبهم؛
  سه وضعیت «اندازه‌گیری‌شده/تخمینی/نامعلوم»؛ قید عرض دیوار (۱۸۰ در برابر ۲۱۰).
- پلان تعاملی: کشیدن و چرخاندن وسیله، قفل وسیلهٔ ثابت، برگرداندن، ویرایش عرض آزاد،
  هشدار مسیر و هم‌پوشانی.
- کیفیت عکس: محاسبهٔ تیزی (واریانس لاپلاسین) و روشنایی روی گوشی؛ حذف متادیتا/GPS با
  رمزگذاری دوبارهٔ تصویر؛ چرخش و جایگزینی.
- جریان سفارش: بدون سفارش موازی، ادامه بعد از بستن اپ، وضعیت‌های صف/ساخت/بررسی/آماده/ناموفق،
  تلاش دوباره با همان شناسه.
- اصلاح موضعی: مصرف سهم فقط در موفقیت، رد شدن با وسیلهٔ ثابت بدون مصرف سهم،
  تاریخچهٔ نسخه‌ها و بازگشت به نسخهٔ قبلی.
- خرید: یکتایی شناسهٔ پرداخت، پرداخت در انتظار، رسید و بازیابی خرید، مسیر ناموفق.
- ذخیره‌سازی محلی و بازیابی وضعیت پس از بستن اپ؛ بزرگ‌کردن نوشته برای دسترسی‌پذیری.
- ابعاد اتاق: عرض و عمق با عدد واقعی جایگزین می‌شود و چیدمان متناسب جابه‌جا می‌ماند؛
  پنجره، درِ بالکن، قید عرض آزاد و مسیر هم با اتاق تازه بازمحاسبه می‌شوند.
- پایلوت: ثبت رویدادهای شروع، تکمیل عکس، ساخت، دیدن، انتخاب، خرید، اصلاح و اجرا؛
  قیف استفاده با درصد و خروجی CSV برای گزارش (حساب من ← پایلوت و اندازه‌گیری).

## آنچه شبیه‌سازی است (و مرز آن)

| مورد | وضعیت | برای واقعی شدن لازم است |
| --- | --- | --- |
| تولید تصویر واقع‌گرایانه | ساخته نمی‌شود؛ خروجی «شماتیک» روی عکس + صحنهٔ برداری نمونه | سرویس تصویر با inpainting/ControlNet روی عکس کاربر |
| تشخیص خودکار وسایل | محدوده‌های نمونه، قابل اصلاح دستی | مدل تشخیص/سگمنتیشن (مثلاً SAM + تشخیص مبلمان) |
| پردازش سمت سرور | شبیه‌سازی زمان‌بندی‌شده روی گوشی | صف کار، ذخیره‌سازی ابری، وضعیت از سرور |
| پرداخت | درگاه نمایشی | درگاه بازار/زرین‌پال + تأیید سرور |
| ورود با شماره | کد نمایشی ۱۲۳۴ | سرویس OTP |
| پنل عملیات | دادهٔ محلی | بک‌اند با نقش‌ها و ثبت رویداد |

## گام بعدی پیشنهادی

1. اتصال یک سرویس تصویر و سنجش نرخ تأیید روی ۲۰ اتاق واقعی (معیار سند: ۸۰٪).
2. بک‌اند کوچک: پروژه، عکس، سفارش، خرید + صف پردازش.
3. بسته‌بندی اندروید با Capacitor، آزمون دوربین/گالری/پرداخت روی دستگاه واقعی.
